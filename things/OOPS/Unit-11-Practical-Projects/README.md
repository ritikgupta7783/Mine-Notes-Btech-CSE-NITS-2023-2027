# Unit 11 — Practical C++ OOP Projects

These projects turn theory into complete programs. Follow them in order. Every project includes requirements, a simple class relationship diagram, class responsibilities, complete C++17 code, expected output, an explanation, test cases and extension ideas.

## Recommended order

1. [Student Profile Manager](01-Student-Profile-Manager/README.md) — classes, data members and methods.
2. [Rectangle and Circle Calculator](02-Rectangle-Circle-Calculator/README.md) — multiple objects, calculations and validation.
3. [Bank Account Management System](03-Bank-Account-Management/README.md) — encapsulation and invariants.
4. [College Result Management System](04-College-Result-Management/README.md) — arrays, validation and derived results.
5. [Library Management System](05-Library-Management/README.md) — composition and object relationships.
6. [Employee Payroll System](06-Employee-Payroll/README.md) — constructors, const methods, static member and calculation logic.
7. [Shape Drawing System](07-Shape-Polymorphism/README.md) — abstract base class and runtime polymorphism.
8. [Multi-class Payroll System](08-Multi-Class-Payroll-System/README.md) — composition, polymorphism-ready design and separation of responsibilities.

## How to use a project
1. Read the requirements and predict the class design before coding.
2. Draw the class relationships in your notebook.
3. Type the code and compile it with g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o app.
4. Compare the program's output with the expected output.
5. Run all listed tests and add at least two edge cases of your own.
6. Try an extension only after the base solution is understood.

These are learning projects, not production software. Real systems may need persistent storage, security, logging, error reporting, concurrency handling and more robust validation.
